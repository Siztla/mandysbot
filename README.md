# Mandy's — обучающий Telegram-бот

Бот для онбординга и обучения персонала ресторана/кафе Mandy's: ценности,
стандарты работы и полное меню (группы → категории → позиции) с фото,
составом, описанием, аллергенами и рекомендациями подачи. Есть встроенная
админ-панель — без доступа к коду и базе данных.

## Структура бота

- **/start** — приветствие про Mandy's, дальше три раздела:
  - **💎 Ценности** — список пунктов с описанием и фото;
  - **📐 Стандарты** — список пунктов с описанием и фото, а если заведены
    вопросы теста — кнопка «🧪 Пройти тест по стандартам» для самопроверки;
  - **📋 Меню** — Группа → Категория → Позиция. У каждой позиции: фото,
    состав, описание, аллергены, с чем подаётся.
- **/admin** — админ-панель (только для администраторов):
  - управление группами меню (создать/переименовать/удалить);
  - управление категориями внутри группы;
  - управление позициями внутри категории (название, фото, состав,
    описание, аллергены, с чем подаётся, предпросмотр «как видит
    сотрудник», удаление);
  - управление пунктами «Ценности» и «Стандарты» (название, описание, фото);
  - управление тестом по стандартам (вопросы, варианты ответов, просмотр
    результатов прохождения сотрудниками);
  - редактирование текста и фото онбординга;
  - управление списком администраторов.

При первом запуске в базу автоматически добавляются 16 групп меню:
Завтраки, Бизнес ланч, To share, Закуски, Сэндвичи, Салаты, Супы,
Паста & ризотто, Мясо & птица, Рыба & морепродукты, Овощи & гарниры,
Десерты, Чай, Кофе, Лимонады, Софт. Их можно переименовывать, удалять и
добавлять новые через админ-панель.

## Установка и запуск

1. Установите Python 3.11+.
2. Создайте и активируйте виртуальное окружение, поставьте зависимости:

   ```bash
   python3 -m venv venv
   source venv/bin/activate        # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Получите токен бота у [@BotFather](https://t.me/BotFather).
4. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot) —
   он понадобится, чтобы получить доступ к админ-панели.
5. Скопируйте `.env.example` в `.env` и заполните:

   ```bash
   cp .env.example .env
   ```

   ```env
   BOT_TOKEN=ваш_токен_от_BotFather
   ADMIN_IDS=123456789,987654321
   DB_PATH=mandys.db
   ```

   `ADMIN_IDS` — список Telegram ID через запятую, которые получат доступ к
   `/admin` сразу после первого запуска. Позже новых администраторов можно
   добавлять прямо из бота (раздел «👤 Администраторы»).

6. Запустите бота:

   ```bash
   python bot.py
   ```

   База данных (SQLite, файл `mandys.db`) создаётся автоматически при
   первом запуске, со всеми таблицами и сидом из 16 групп меню.

## Как наполнять контент

Всё наполнение делается только через Telegram, из раздела `/admin`:

1. **Меню**: «📋 Управление меню» → выбрать/добавить группу → «📂 Категории»
   → добавить категорию → «🍽 Позиции» → добавить позицию → заполнить её
   карточку (фото, состав, описание, аллергены, с чем подаётся).
2. **Ценности / Стандарты**: соответствующий раздел в админке → «➕
   Добавить пункт» → заполнить название, описание, при желании — фото.

   Если пунктов сразу много (например, наполняете раздел большим текстом
   целиком), удобнее «📥 Массовый импорт»: пришлите одним сообщением (или
   файлом `.txt`, если текст длинный) список пунктов, где каждый пункт —
   первая строка это название, дальше до разделителя — описание (можно в
   несколько строк, пустые строки внутри сохраняются). Разделитель между
   пунктами — отдельная строка из трёх знаков равно: `===`

   ```
   Миссия
   Текст миссии, можно в несколько предложений.
   ===
   Ключевая идея
   Текст ключевой идеи.
   ===
   Эстетика
   Мы верим, что красота — это не роскошь, а ежедневная необходимость.
   ```

   Бот создаст по пункту на каждый блок и покажет итоговый список названий.
   Если формат не распознан (не нашлось ни одного пункта), бот попросит
   прислать текст ещё раз, ничего не создавая.
3. **Онбординг**: раздел «📝 Онбординг» → изменить текст и/или фото
   приветственного сообщения.
4. **Тест по стандартам**: раздел «🧪 Тест по стандартам» → «➕ Добавить
   вопрос» → ввести текст вопроса → ввести варианты ответа, каждый с новой
   строки, отметив правильный звёздочкой в начале строки:

   ```
   *Обязательно поздороваться и предложить меню
   Молча проводить к столу
   Подождать, пока гость сам позовёт
   ```

   Нужно минимум 2 варианта, и правильный должен быть отмечен ровно один.
   Результаты прохождения (кто, с каким баллом, когда) смотрите там же в
   «📊 Результаты сотрудников». Пока в тесте нет ни одного вопроса, кнопка
   «Пройти тест» сотрудникам не показывается.

Любое поле можно отредактировать повторно в любой момент — правки видны
сотрудникам сразу же.

## Технологии

- Python 3 + [aiogram 3](https://docs.aiogram.dev/) (long polling)
- SQLite через `aiosqlite`
- Хранение состояний диалога — `MemoryStorage` (в оперативной памяти). Для
  продакшена с несколькими процессами можно заменить на `RedisStorage`.

```
│   └── admin/
│       ├── root.py              # /admin, главное меню админки, отмена
│       ├── groups.py            # CRUD групп меню
│       ├── categories.py        # CRUD категорий
│       ├── positions.py         # CRUD позиций + все поля карточки
│       ├── sections.py          # CRUD пунктов "Ценности"/"Стандарты"
│       ├── onboarding.py        # редактирование онбординга
│       └── admins.py            # управление администраторами
└── utils/
    ├── access.py               # проверка is_admin
    ├── filters.py               # aiogram-фильтр IsAdmin
    ├── formatting.py            # сборка текста карточек
    └── msg.py                   # edit/пересоздание сообщений (текст ⇄ фото)
```

## Деплой на BotHost (bothost.ru)

Если хостите через [BotHost](https://bothost.ru/) с деплоем из GitHub:

1. Запушьте этот проект в GitHub-репозиторий как есть — `requirements.txt`
   и точка входа `bot.py` уже в корне, ничего переносить не нужно.
2. В настройках проекта на BotHost укажите переменные окружения:
   `BOT_TOKEN`, `ADMIN_IDS` — как в `.env.example`.
3. **Важно:** обязательно задайте `DB_PATH=/app/data/mandys.db` —
   по документации BotHost именно `/app/data` сохраняется между
   редеплоями. Без этой переменной путь по умолчанию (`mandys.db`)
   будет создаваться в файловой системе контейнера, а после следующего
   деплоя вся база (созданные группы, категории, позиции, ценности,
   стандарты, список админов) может быть потеряна.
4. Долгий поллинг (long polling), который использует бот по умолчанию,
   не требует открытого порта — для персистентного процесса (как на
   BotHost) он подходит без доработок.

Точные названия полей в интерфейсе BotHost могут отличаться — при
расхождениях сверяйтесь с их актуальной документацией на
bothost.ru/docs/.

## Деплой на VPS

Для постоянной работы бота (24/7) на своём сервере/VPS разверните его
под `systemd` или в Docker, с автоперезапуском процесса. Простейший
пример unit-файла `systemd`:

```ini
[Unit]
Description=Mandy's training bot
After=network.target

[Service]
WorkingDirectory=/path/to/mandys_bot
ExecStart=/path/to/mandys_bot/venv/bin/python bot.py
Restart=always
EnvironmentFile=/path/to/mandys_bot/.env

[Install]
WantedBy=multi-user.target
```
